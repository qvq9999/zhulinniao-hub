# ADR-005: 本地存储采用「JSON 文件为主 + SQLite 缓存为辅」

## Status
Accepted (2026-10-16)

## Background
原版配置散落于 `UI\Configs\*.json`（EQPreset、EQ2Preset、LEDDefaultConfig、LEDColorArrayConfig、DefaultProfiles、HeadTracking、HyperHearDefaultSetting、HyperHearGameConfig、VoiceAccessConfig、Settings），Path.txt 指明 ProgramData 根：`Cmedia\CM002X1`。

新产品需要在本地持久化：
1. 用户配置档（EQ/空间音频/LED/降噪等 profile）。
2. 可迁移的原版配置（需 import 老配置）。
3. 应用运行时状态（窗口、上次设备、Feature Flag 等）。

候选：
- 纯 JSON 文件（结构化目录）
- SQLite（`rusqlite` / `tauri-plugin-sql`）
- Windows 注册表

## Decision
采用 **JSON 文件为主 + SQLite 为辅**：

- **JSON 文件（主）**：用户可见、可备份、可迁移的配置档与导入的原版配置，按 profile 一文件，存于 Tauri `appConfigDir` 下 `profiles/`。
- **SQLite（辅）**：设备历史、操作日志、Feature Flag、需要查询/事务的运行时数据，存于 `appDataDir` 下 `hub.db`。
- **绝不使用注册表**存放业务配置（APO PKEY 除外——那是驱动侧既有机制，不是本应用存储）。

路径策略（Tauri v2 标准目录，禁止硬编码绝对路径）：
- 配置：`{appConfigDir}/profiles/*.json`、`{appConfigDir}/settings.json`
- 数据：`{appDataDir}/hub.db`
- 迁移：`{appConfigDir}/migrated/`（原版 import 落地的只读副本）

迁移策略：
- 首次启动检测原版目录（ProgramData `Cmedia\CM002X1` 或用户指定路径），提供「导入旧配置」向导。
- 原版 10 个 JSON 一律经**本地 JSON Schema 校验**后再转成新 schema（见 `docs/schemas/`），校验失败不阻塞应用启动，只跳过该文件并记录日志。
- 迁移是**幂等**的：带 `migratedAt` 与来源指纹，重复导入不覆盖用户已修改配置。

## Consequences
正面：
- 配置 JSON 用户可直接查看/备份，符合桌面工具习惯。
- SQLite 承担查询类数据，避免 JSON 全量读写。

负面：
- 双存储需明确「哪类数据放哪」的边界，避免配置漂移。
- 需要版本化迁移脚本（schemaVersion 字段）。
