# ADR-004: HID 设备识别采用「VID 白名单 + PID 家族运行时枚举」

## Status
Accepted (2026-10-16)

## Background
CM002X1 在原版 INF 中并非单一 PID，而是**同一驱动的多个 USB 身份**（OEM/白标/不同批次）。来源：

- `ApoDriver\Driver\CM002X1.Inf`：
  - `USB\VID_0D8C&PID_0334`
  - `USB\VID_4C4A&PID_4255`
  - `USB\VID_20F8&PID_A962 / A963 / A964`
  - `USB\VID_0E6A&PID_0110`
  - `USB\VID_046A&PID_01ED`
- `ApoDriver\Apo\01_EXTENSION\CM002X1_Ext.inf`：与上完全一致的 PID 家族。
- `UI\Configs\Settings.json`：`LEDControlDevice_VID` / `JokkooControlDevice_VID` / `GaieochosControlDevice_VID` / `TekeaControlDevice_VID` 均为 `0D8C`。
- `UI\Configs\HeadTracking.json`：`FWVid=0D8C`, `FWPid=0337`（固件/头动子设备另一 PID）。

**C-Media 主 VID = 0x0D8C**，但存在多个 OEM VID。若写死单一 PID，将无法覆盖不同批次/贴牌设备。

## Decision
设备识别采用 **VID 白名单 + PID 家族运行时枚举**：

- **VID 白名单**（枚举过滤条件，至少包含）：`0x0D8C`、`0x4C4A`、`0x20F8`、`0x0E6A`、`0x046A`。
- **PID 家族**（白名单内的已知家族，运行时逐个匹配，禁止写死单一 PID）：
  - `0x0334`
  - `0x4255`（VID 4C4A）
  - `0xA962 / 0xA963 / 0xA964`（VID 20F8）
  - `0x0110`（VID 0E6A）
  - `0x01ED`（VID 046A）
- 设备识别流程：枚举 HID/音频设备 → 过滤 VID ∈ 白名单 → 在 VID 匹配下再校验 PID ∈ 家族（或复合设备 `MI_00`）→ 命中即视为 CM002X1 家族设备。
- **运行时枚举**：配置只保存 VID 白名单与「已知 PID 家族」列表；实际连接的 PID 从运行时枚举结果得到，不硬编码到代码分支。新增家族 PID 只改配置/常量表，不改控制逻辑。
- 音频端点（APO 通道）与 HID 端点分别枚举，二者以 VID 家族关联。

## Consequences
正面：
- 覆盖白标/多批次设备，提升兼容性。
- 新 PID 可通过扩展家族表低成本接入。

负面：
- 需处理「音频端点」与「HID 端点」PID 不一致的匹配（如 HeadTracking `0337` 属于关联子设备）。
- 枚举到同 VID 非目标设备需二次校验，避免误识别。
