# ADR-001: 使用 Tauri v2 承载桌面应用

## Status
Accepted (2026-10-16)

## Background
原版竹林鸟朱雀耳机（CM002X1，C-Media Xear 方案）驱动面板为 WPF/.NET（XearONE.exe），仅支持 Windows，渲染层老旧、安装体积大、难以现代化。重构目标：保留全部设备控制能力，同时获得更小安装体积、现代渲染层与 React 前端生态的可维护性。

候选承载方案：
- Electron（内嵌 Chromium）
- Tauri v2 + React 18.3 + TypeScript 5.x + Vite 6
- 延续 WPF 现代化改造

关键约束：
1. 必须调用 Win32 能力（HID、Windows 音频 PropertyStore / APO），需要 Rust 侧或原生互操作。
2. WebHID 在 WebView2 不受支持，Web 直连 HID 路线 P0 排除。
3. 需要托盘常驻、随系统启动、单实例。

## Decision
选择 **Tauri v2 + React 18.3 + TypeScript 5.x + Vite 6**。

理由：
- 前端（WebView）与核心能力（Rust core）通过 command 边界解耦，职责清晰，便于前后端并行开发。
- Rust 侧可直接使用 `windows` crate（setupapi / hid / ksuser）实现 Tier2 原生直连。
- 复用系统 WebView2，无需内嵌 Chromium，安装体积与内存占用显著低于 Electron。
- Tauri v2 原生提供 sidecar、tray、autostart、single-instance、updater 等桌面必备能力。

## Consequences
正面：
- command 契约强约束前后端边界，利于契约驱动开发与 Mock。
- 分发包小，内存占用低。
- Rust 侧安全模型（capability / permission）可控。

负面：
- 依赖 WebView2 运行时（Win10/11 普遍内置，旧系统需引导安装）。
- 引入 Rust + .NET 双工具链（cargo + dotnet）。
- Tauri v2 部分插件仍在演进，升级需关注 changelog 与破坏性变更。
