# ADR-006: 安装包内置 C-Media 驱动组件（免单独安装原版驱动）

## Status
Accepted (2026-10-17)

## Background
用户要求：只安装本项目即可使用全部功能，不再依赖单独安装原版驱动包。

取证结论（见 `docs/通道全景图.md`、`.workbuddy/memory/2026-10-17.md`）：本机可用功能中，
9 项音效（均衡器 / 音频明亮化 / 人声清晰化 / 动态低频 / 智能音量 / 7.1环绕 / 环绕扩增 /
麦克风降噪 / 麦克风均衡）**不**由应用进程产生声音，而是：

1. `CM002X1.SYS` 提供播放/录音端点（音量、静音、平衡的前提）；
2. `CmApoIce.dll` 作为 APO 在 `audiodg.exe` 内执行 DSP；
3. `CM002X1_Ext.inf`（`Class=Extension` + `AddComponent=CMAPO`）在设备硬件键注册 APO 的
   `CompositeFX_*EffectClsid`，并创建 `FX\0|FX\1\%CAPX*_PROPERTYSTORE_CONTEXT%\User` 全部属性与默认值。

应用写注册表只是「存数字」，缺任一层都没有消费者。因此「只装本项目」在技术上等价于
「本项目把这三层一起装上」。

候选：
- A. 安装包内置驱动组件，静默安装（pnputil）
- B. 自研 APO 替换 `CmApoIce.dll`
- C. 维持现状，标注「需另装驱动」

## Decision
采用 **A**。

- 驱动文件内嵌进安装包：`app/src-tauri/resources/driver/{base,apo,ext}`，9 个文件逐字节取自
  `C:\Windows\System32\DriverStore\FileRepository` 的厂商签名包（INF/CAT/SYS/CRT/DLL），**不做任何修改**
  （改一个字节就会破坏 CAT 签名）。
- `tauri.conf.json`：
  - `bundle.resources`：9 条显式映射 → `$INSTDIR\driver\{base,apo,ext}\...`
  - `bundle.windows.nsis.installMode = "perMachine"`：`pnputil` 必须提权，安装器整体以 admin 运行
  - `bundle.windows.nsis.installerHooks = "installer-hooks.nsh"`
- `installer-hooks.nsh`：
  - `PREINSTALL`：按由浅到深顺序建目录链（含 `base\x64`）。**必须做**：NSIS 的 `CreateDirectory`
    不递归，且 Tauri 生成的 `CreateDirectory` 顺序不稳定（两次构建分别为 `base\x64` 在首 / 在尾），
    子目录缺失会让 `File /oname=...\子目录\文件` 直接中止安装（exit 2）。
  - `POSTINSTALL`：`nsExec` 依次执行 `pnputil /add-driver <inf> /install`，顺序 base → apo → ext；
    退出码 0/3010 视为成功，`error`（无法启动）折算 9999；`3010` 时 `SetRebootFlag`。
  - 结果写 `HKLM\SOFTWARE\ZhulinniaoHub\Driver`（`BaseRc/ApoRc/ExtRc/Ok/Log/DriverRoot`）
    与 `$INSTDIR\driver-install.log`，供应用与售后判断驱动是否就绪。
  - 失败**不中断**应用安装（装置信息/音量仍可用），但弹窗说明音效不可用并给出退出码与日志路径。
  - `PREUNINSTALL`：只清理 `$INSTDIR\driver` 与注册表记录；**不**卸载 DriverStore 里的驱动包
    （卸载会让耳机失去音频端点，与厂商安装器行为一致）。
- 不采用 B：自研 DSP 会重写音色，直接违反「功能必须与原版一致」的铁律，且 Windows 11 对 APO 有签名门槛。

## Verification（已执行）
1. **字节一致性**：用同一份 `.nsh` 编译独立测试安装器，静默安装后 9 个文件 SHA-256 与原件逐一相同（9/9）。
2. **驱动包完整性**：把随包的 `CM002X1.Inf` 交给 `pnputil /add-driver`，返回 0（识别为 `oem26.inf`，
   「系统中已存在」），证明 INF/CAT 配对完整、签名未被破坏。
3. **钩子逻辑**：静默安装后 `driver-install.log` 内容正确（`base_rc/apo_rc/ext_rc/ok`），
   目录结构为 `driver\{base{x64},apo,ext}`。
4. **提权语义**：非提权环境下 `nsExec` 对 `pnputil` 返回 `error`（cmd.exe 正常返回 3），
   证明 9999 分支语义正确，也证明 `pnputil` 必须提权 → `installMode` 必须是 `perMachine`。
5. **体积**：驱动 10,242,286 B + 应用 3,293,184 B → 安装包 2,869,264 B（LZMA solid，约 21%）。

未在本次会话验证：提权后的 `pnputil /install` 实际落地（会话无提权，无法触发 UAC）。
该步需一次真实安装确认，判据是注册表 `Ok=1` 且三项 rc 为 0。

## Consequences
正面：
- 用户只需运行一个安装程序，不再需要原版驱动包或原版 UI 目录。
- 驱动就绪状态可被程序读取（`HKLM\SOFTWARE\ZhulinniaoHub\Driver`），可据此避免「控件假生效」。

负面 / 风险：
- **合规**：随包分发 C-Media 的签名驱动二进制需取得厂商授权；未获授权前不应对外发布该安装包。
- **维护**：厂商更新驱动后需人工同步 `resources/driver` 并重新出包。
- **安装模式变更**：`perMachine` 写入 `HKLM` 与 `Program Files`，与旧版按用户安装（`HKCU` +
  `%LOCALAPPDATA%`）互不可见，升级前建议先卸载旧版。
- 卸载不回收驱动包，`DriverStore` 会保留（约 10 MB）。
